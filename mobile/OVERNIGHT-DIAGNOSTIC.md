## 查询方式

均使用 `/marketdata/v1/pricehistory`，`frequencyType=minute`、`frequency=1`、`periodType=day`、`needExtendedHoursData=true`、`needPreviousClose=true` 和检查时刻的 `endDate`。

| 查询 | 时间窗口 | 返回根数 | HTTP | 无效/重复根数 |
|---|---|---:|---:|---:|
| SNDU，与 App 0.5.5 相同 | `period=10` | 8,281 | 200 | 0 / 0 |
| SNDU，明确起止时间 | `startDate=endDate-10天`，不传 period | 4,190 | 200 | 0 / 0 |
| QQQ，对照 | `period=10` | 11,836 | 200 | 0 / 0 |

`period=10` 实际返回跨越超过 10 个日历日；明确日期的查询窗口不同，不能仅用总根数比较。两个 SNDU 查询的重叠日期夜盘根数一致。

## 结论边界

- 不能再将“所有 Schwab 历史 API 都没有夜盘数据”作为解释：本次响应已经包含夜盘。
- 更换为明确 `startDate` 没有补回 SNDU 近期缺失的夜盘，因此没有证据支持仅修改这个参数就能修复。
- 数据缺失不等于没有成交，也不等于不支持夜盘交易；此次没有验证证券交易资格或实时流在夜盘的覆盖。
- 客户端仍应保留已有夜盘蜡烛，不插值或用模拟行情填补缺口。恢复最近夜盘历史需要上游提供对应数据，或后续接入经验证的替代数据源。
- 此次只记录诊断结果；没有构建新 IPA，也没有声称修复了 SNDU 缺失的历史。
