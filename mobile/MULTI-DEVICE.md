# 多设备服务器连接

目标：两个个人设备使用同一个 Schwab API 应用，服务器负责唯一的券商授权会话和令牌刷新。手机保存服务器地址及各自的设备访问密钥，不再分别刷新 Schwab 令牌。

## 验收要求

- 两个设备共享账户授权状态；一台完成 Schwab 授权后，另一台刷新即可使用。
- 设备访问密钥分别生成、分别撤销；手机断开只移除本机连接，不能注销另一台的券商会话。
- 多个请求遇到访问令牌到期时，只进行一次刷新；令牌仅加密保存在服务器，不通过接口返回手机。
- 下单核对结果绑定发起设备。另一台不能提交该结果，同一结果只能提交一次。
- 两台设备的写操作共用服务器交易锁。核对失效时明确要求重新核对，不自动更换用户已核对的订单。
- 网络中断后的下单/撤单不能自动重试；结果不明必须保留锁定并人工核实。
- 行情通过服务器统一订阅并分发，离开图表或进入后台后释放手机订阅；服务器订阅过期后清理。
- 所有联网测试先使用虚构账户；真实环境只读验收，真实交易由用户本人完成。

## 部署前提

需要确认用户服务器的地址、系统和可用 SSH 连接。公网手机访问必须使用 HTTPS；应用服务仅监听服务器本机，通过 TLS 反向代理提供服务。不得把本地调试工具直接开放到公网，也不得在访问日志中记录 OAuth 回调查询字符串或设备密钥。

独立生成服务器加密密钥、设备访问密钥；这些与 Schwab Client ID / Secret 是不同用途的凭据。个人配置、授权数据、运行目录和密钥不进入 GitHub。

如果使用服务器自动接收 OAuth 回调，需要把实际 HTTPS 回调地址登记到 Schwab 开发者门户。授权仍在 Schwab 官方页面完成，服务器不接收账户密码。服务器收到回调后，两台设备共享更新后的授权状态；浏览器自动关闭/返回 App 是独立的手机体验步骤，不能与服务器授权成功混为一谈。

切换前不要让旧直连版继续重新授权或自动刷新同一应用会话。保留可回退的源代码和旧配置，但由用户在实际迁移时停止旧连接。
